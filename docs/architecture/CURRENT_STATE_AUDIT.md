## Текущий поток состояния

`localStorage string → JSON.parse → hydrateState → AppState → view callbacks/planner → setState(JSON.stringify) → custom event/storage event → полный hydrate`.

- Ключ: `family-meal-planner-state-v1`, событие: `family-meal-planner-change`.
- `useSyncExternalStore` обслуживает тот же браузер и событие `storage` других вкладок. Это не серверная синхронизация и не защита от конкурентной перезаписи.
- `hydrateState` объединяет seed-рецепты с сохранёнными, генерирует меню для недостающих обедов, восстанавливает непустой список. Чтение выполняет неявные преобразования.
- `commit` сохраняет один undo snapshot и подставляет `buildShoppingList`, когда длина списка 0. Некоторые экраны вызывают `setState` напрямую и обходят undo.
- `AppState` хранит и предметные данные, и cooking session; active section, формы, toast, undo остаются в React state. Разделение частичное, не полностью отсутствующее.

## Сопоставление с целью Павла

| Звено | Состояние сейчас | Минимальное недостающее |
|---|---|---|
| Предпочтения семьи | Есть редактируемые профили и scoring | Структурированные hard/soft rules, scope по человеку/дате |
| Меню | Есть генератор и ручные действия | Корректные ограничения, даты, порции, accept/draft, устойчивые IDs |
| Рецепты | Есть редактор и связи с блюдами | Один источник состава, revision, completeness, проверка семейной подборки |
| История выбора | Только часть факта готовки/feedback | Принятие, замена, пропуск, повтор, stable references |
| Вероятностные запасы | Есть ручные inventory/leftover/freezer | Сигналы, происхождение, интервал/qualitative estimate, политика уточнения |
| Автопокупки | Есть агрегация и перенос checked → inventory | Единицы, quantity provenance, reconciliation и идемпотентность |

Вывод: это функционально насыщенный локальный MVP с подходящим UX. Главный разрыв — достоверность состояния и непрерывность цепочки, а не отсутствие backend-фреймворка или LLM.
